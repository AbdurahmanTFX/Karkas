# 0016 — Imported projects: schema first, and the project's own build

Status: accepted (deviation from spec 4.6, 13.1 and ADR 0009)

## Context

The Blobby Volley 2 experiment (an imported project, ~25k lines, its own CMake and Boost tests)
showed three places where Karkas worked only for projects it generated itself:

1. A new block of an imported project lists the files it will live in (`files src/Effects.cpp`).
   E09 refused the proposal while the files did not exist, so the agent wrote code first and
   proposed the card afterwards — the opposite of "schema first".
2. `karkas approve api` froze the contracts and then failed on write_cmake: the project's
   CMakeLists.txt is not generated by Karkas.
3. `kk_run_tests` / `karkas test` also started with write_cmake and failed the same way, so the
   agent built and tested through the shell, outside Karkas.

## Decision

1. A listed file that does not exist is warning W07 ("does not exist yet"), not E09. The block
   stays in design until the file exists (status comes from the code, as for native leaves).
   E09 keeps the other two rules: a file belongs to one block and is not inside another block's
   folder.
2. A project "has its own build" when its CMakeLists.txt is not generated by Karkas
   (`code::has_own_cmake`). Then:
   - `karkas approve api` freezes the contracts (the headers of imported blocks are their api),
     writes skeletons and mocks of native leaves only, and generates no probe and no
     CMakeLists.txt; it says so and tells to add new source files to the project's build.
   - `TestService::build_and_test` (kk_run_tests, `karkas test`, the agents) builds the project
     as it is and runs its own tests as a whole: `[test] command` of karkas.toml (a shell command
     from the project root), or ctest in the build folder. The output is compressed for a model
     (failure and summary lines, colours removed). Without a command and without ctest tests it
     says how to configure it. Results are not recorded per block (they cannot be attributed).
3. New keys of karkas.toml: `[project] cmake_args` (extra configure arguments, also for projects
   Karkas generates) and `[test] command`.

## Consequences

- In an imported project the method works end to end: card first (W07 until the file exists),
  approval, freezing, and contract tests run by kk_run_tests in the project's own test suite.
- Per-block test status (passing/failing) stays unavailable for imported blocks.
